# 跨智能体交接检查

一份 `TEMPLATE.md`，每任务一份实际记录。同任务换 Agent 时继续更新原记录，由当次执行者维护；总索引只在任务登记、状态、负责人或位置变化时更新。

## 日常两条命令

在主项目目录运行（也可双击 `协作检查.cmd` 查看摘要）：

```powershell
.\协作检查.cmd status
.\协作检查.cmd check
```

第一条显示实际工作树、分支、HEAD、规则/索引位置、Git 状态和钩子；第二条检查相对 HEAD 的工作区、暂存区及未忽略未跟踪文件。不创建记录，不改代码，不自动运行历史任务。

新任务复制模板后填实，并在总索引登记。完成重要阶段或验证后保存进展，交接、暂停、收工时补齐已完成、未完成、决策原因、验证和下一步。实际状态从六种中选一项：计划、进行中、待接手、待确认、受阻、已完成。

## 提交检查

```powershell
# 仅准确暂存本任务文件；新任务首次登记时同时暂存 CURRENT.md
# git add -- <本任务代码> handoffs/<本任务>.md CURRENT.md
.\协作检查.cmd check --staged
```

有代码/构建/依赖/自动化变更时，必须在同一暂存快照中新增或更新有效任务记录。记录的 `变更文件` 章节以列表项逐行填写反引号包裹的精确路径，覆盖这些文件，重命名包含两侧，删除包含原路径。旧记录仅仅存在不足以通过。纯文档变更不强制产生新任务；有改动的任务记录仍需符合格式。

`验证证据` 必须有 `命令` 和 `结果`。尚未执行可以如实填“未执行”，同时填写 `原因`。失败结果也可记录；这个检查验证交接结构与范围，不代替功能测试、不保证描述真实。

若检查报占位符、缺章节或范围遗漏，修正实际记录后重跑。不要通过复制空模板、仅填“测试通过”或改不相干的记录应付检查。

## 本机 Git 钩子

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/install_handoff_hook.ps1
# 需要撤销本工具的安装时：
# powershell -NoProfile -ExecutionPolicy Bypass -File tools/install_handoff_hook.ps1 -Remove
```

安装器只设置本仓库本机的 `core.hooksPath`，不改系统设置，不覆盖已有自定义钩子。路径指向安装所在工作树的 `.githooks`，同仓库的其他 worktree 也共用它；钩子从实际提交目录读取 index。

本机旧研究分支无需复制整个主项目：可以调用主项目检查器并显式传 `--repo`，其任务记录随研究分支代码提交。其他机器需要取得检查脚本和钩子并重新安装。安装来源工作树应保留原路径，移动前需重新安装。不要只因 `pre-commit` 文件存在就认定其他工具会读取项目规则。

```powershell
& 'D:\PM Stack\PM Stack\.venv-review\Scripts\python.exe' 'D:\PM Stack\PM Stack\tools\handoff.py' status --repo 'D:\PM Stack\PM Stack Agent'
```

主项目保持唯一总索引，登记研究任务的实际目录、分支及记录相对路径。研究分支没有 `CURRENT.md` 时，检查器只提示索引缺失，仍强制检查代码与任务记录；已有本地索引时，候选记录必须被该快照的索引引用。索引仅作导航，检查不会读取其他工作树记录替代本次提交证据。

## CI 与适用边界

`.github/workflows/handoff-check.yml` 在 PR 和 main 推送上运行独立回归，然后用 `check --base <提交>` 检查本次变化范围，证据从 HEAD 读取。它保证范围内的代码变更配有记录；本地钩子才检查单次暂存提交。首次启用不追溯旧历史。

配置文件须提交推送后才在远端运行。要阻止检查失败的 PR 合并，仓库规则还需将 `handoff-check` 设为必需检查；本工具没有自动修改远端规则。直接推送后的 CI 失败也不能撤销已推送的提交。本地钩子可被 `--no-verify` 跳过，不能单独作为无法绕过的保证。

检查只读取 Git/文档，不读取模型密钥、应用配置或用户数据库。除安装命令外，它不会修改 Git 配置、暂存、提交或推送。

## 发布

先提交其他开发改动，准备本次发布记录，在 `变更文件` 中列出版本文件、更新清单、新 spec 和旧 spec 归档的两侧，再运行：

```powershell
.\.venv-review\Scripts\python.exe publish.py --handoff handoffs/<发布任务>.md
```

也可双击 `发布新版本.bat` 后输入记录路径。发布前要求暂存区为空、工作区仅有该记录和可选的 `CURRENT.md` 改动，避免将未提交源码打入发布包。预检失败不改版本、不开始构建。提交前只加本次记录和必要索引，并显式执行暂存检查；不会自动暂存其他任务记录或跳过钩子。

## 工具接入语句

在每种 Agent 工具的项目规则入口中指向仓库 `AGENTS.md`。首次接入或换工作目录时先验证是否读到规则，不假定所有工具都识别同一文件名。

```text
本次任务：填写目标和验收条件。
先读 D:\PM Stack\AGENTS.md 及主项目 AGENTS.md、CURRENT.md。
运行协作检查的 status，确认实际工作树和本次任务记录。
开发中维护该记录；收工先做相关验证，再运行 check。
提交时一并暂存本任务记录并通过 check --staged，说明未完成事项和下一步。
```
