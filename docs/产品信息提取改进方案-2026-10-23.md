# PM Stack 产品信息提取改进方案

> 方案调整：用户指出逐字段结构化的首期工作量过大、跨类目复用不足。优先采用下述轻量方案；后文完整方案作为按需扩展清单，不再作为首期必做范围。

**当前推荐：复用自定义字段，增加通用的批量归一化**

保留现有“字段名称＋提取说明”入口。新增类目通常只需配置想提取什么，不为该类目编写专用程序。字段类型、标准表达和别名可以由AI根据字段说明与代表样本建议，不要求用户事先设计完整的数据结构。

首期流程：现有提取结果 → 按字段语义汇总唯一原始值及频次 → AI提出等价表达映射 → 程序检查及差异预览 → 固定映射应用 → 保存原值、标准值和映射版本。

例如，同一含义的线长字段中，`1Metre / 1 Metre / 1 m`映射到`1 m`；颜色字段中，`Black / black / 黑色`映射到`黑色`；新类目的镜头字段中，`Single lens / 单镜头`可建议映射到`单镜头`。这些都是字段说明和映射数据，无需各写一段归一化程序。

通用程序只承担映射读写、字段范围、原文保留、确定性应用、差异预览、版本与结果验证。明确的单位转换可复用一个通用组件；不能只凭任意字符串形式就启用数值换算。

首期只增加三个能力：

1. 字段唯一值与频次汇总，携带必要的代表证据和变体/对象上下文。
2. 字段级映射建议及预览：哪些只是写法变化、哪些含义不明或有实质差异；允许保持原样。
3. 固定映射的应用与复用：已接受的映射按字段语义与版本保存；新增表达才请求补充建议，规则变化展示差异。

映射建议按字段批量处理，不为每个商品额外调用一次AI；大词表分批处理。首次建议与有语义变化的修改先预览，不能让每轮AI重新生成并直接替换全部标准。跨类目复用必须先确认字段含义相同，不能仅按同名共享词表。

明确边界：

- 字段说明仍需明确希望提取的对象，这是任务配置，不是重新开发；含义无法从输入确定时需要澄清或保留未知。
- 等价表达归一化不会替代事实纠错；同一商品1m与2m的矛盾不能靠映射消除。
- 只保存`65W`的旧值可能已丢失单口/总功率范围；此时应保留或回查证据，不能用全局映射补出含义。
- 黑白可选、黑白机身、部件黑白不能共用一个无上下文映射；组合、多值和新值允许保留。
- 固定映射使已接受的标准化过程可重复，但不证明映射或原始提取事实必然正确。
- “无”被当成缺失、补抓站点等既有缺陷作为独立修复项，不为每个类目重复实现。

暂不作为首期前置条件：全面拆分USB和功率结构、通用复核中心、长期结果数据库、所有字段强类型化、完整来源裁决系统。仅在实际分析需要更细字段时，通过配置先尝试拆成多个普通提取字段；确实有复杂跨字段推理需求再增加专用扩展。

**二、总体流程**

输入工作簿与商品身份 → 保存来源快照 → 收集字段候选及证据 → 程序标准化 → 类型与关系校验 → 自动接受或进入复核 → 保存结果版本 → 写回标准值。

1. 商品身份：站点＋子 ASIN＋必要的变体信息。记录输入链接、最终链接、页面子体、采集时间。仅有 ASIN 时先用任务站点；站点不明时标记，不能默认为美站。共享父体、跨站点与不同子体的值不直接互补。
2. 来源快照：标题、五点、参数、当前变体标签、图片均有独立 `source_id`；记录来源列、图片编号/内容摘要和内容哈希。没有采集到的来源与采集失败分别记录。
3. 候选收集：AI 返回原始值、候选结构、逐字段证据和适用范围。证据文本必须来自实际输入；图片必须引用本轮已提供的图片编号。来源内容作为商品数据处理，不允许其指令改变提取规则。
4. 标准化：共享程序按字段规则转换；只做已定义且可追溯的变换。同一个输入与规则版本重复执行，结果相同；标准化后再次执行不产生变化。
5. 校验与选择：同时看类型、单位、证据、商品身份、取值范围、字段关系及来源矛盾。模型自报置信度不能单独触发通过。
6. 写回：标准值用于业务筛选；原始候选、证据和版本保存在日志/结果库。冲突值不伪装成已确认事实。

不必对所有商品重复调用全部图片。默认补缺、格式异常和高风险字段；需要核对已有值时按字段补充证据。只有实际检查过的来源才能支持“一致”结论。

**三、字段配置：通用类型＋领域规则**

字段使用稳定内部 ID，中文显示名可修改。不同品类同名字段可以具有不同语义，例如排插“插孔数”与自动开关“总插孔数（工具插孔数）”不能仅凭名称复用同一规则。

每个字段至少配置：显示名称、含义与计量对象、数据类型、标准单位、允许值/别名、是否多值、允许来源、缺失处理、展示格式、校验规则和规则版本。用户日常只需选择预设类型和单位，高级规则折叠显示。

| 通用类型 | 用途 | 处理方式 |
|---|---|---|
| 整数 | 插孔数、包装数、接口数量 | 验证整数与计数对象；未知不默认 0 或 1 |
| 数值＋单位 | 线长、直径、功率、电流 | 保留原单位，转换标准单位；按维度校验 |
| 单选 | 工作模式、明确的形态分类 | 选择已配置标准值；新值成为待映射候选 |
| 多选集合 | 基础颜色、安全功能、协议 | 去重并按固定顺序显示；保留组合和角色 |
| 布尔值 | 是否支持某项功能 | true/false 为已知事实；null 表示未知 |
| 范围/条件值 | 温度范围、电压条件功率 | 保存上下限或条件列表，不能只取最大值 |
| 尺寸 | 长宽高、探头规格 | 保留维度名、轴序、单位；未知轴序不擅自命名 |
| 结构化对象 | USB端口、端口功率、控制分组 | 保存子字段，支持部分已知 |
| 自由文本 | 特殊卖点、备注 | 仅规范空白与展示，不强制压缩成有限类别 |

数值原始精度与展示精度分开。业务分档（如“约1m档”）是额外派生字段，不能覆盖精确长度。异常范围只提示复核，不截断或改写数值。

**四、颜色具体规则**

同时保留三种信息：商品原始色名、基础色集合、可选的部件/主辅色。基础色字典及别名由配置管理。

| 原始信息 | 处理结果 |
|---|---|
| Black / black / 黑色 | 基础色＝黑色，保留原文 |
| Black and Yellow，明确描述同一机身 | 基础色＝黑色＋黄色；不压成黑色 |
| Yellow body with black cable | 主体黄色、线缆黑色；按字段定义决定主体颜色集合 |
| Available in black or white | 可选颜色列表；不能直接认定当前子体是黑白双色 |
| Space Gray / Graphite / Ivory | 保留商品色名；只有配置了映射才转成基础色，不自动视为普通灰/白 |
| 文字说白色，当前子体图片看似黑色 | 保留两份候选，核对变体和来源，进入冲突/待复核 |

多色集合按固定字典顺序显示；主辅色另存，不能通过排序隐含主色。图片中背景、包装、装饰物与配件颜色不自动计入主体。光照、遮挡、渲染图不明确时可以未知。看到没有列入字典的新颜色，不自动扩充标准枚举或归入一个已有颜色。

**五、USB 接口与快充具体规则**

USB 使用一组结构化子字段：A口数、C口数、其他类型口数、类型未区分口数、明确总数、端口角色（输入/输出）、协议。缺失子字段可为未知。

| 原始信息 | 标准记录与展示 |
|---|---|
| 完整配置为 2 USB-A + 1 USB-C | A＝2，C＝1，总数＝3；展示 2A+1C |
| 共4个USB，未区分形态 | 总数＝4，A/C未知；展示 4USB（类型未区分） |
| 只知道“带USB” | 存在＝是，数量未知；不能填 1 |
| 明确无USB | 存在＝否，总数＝0；不能被当作缺失反复提取 |
| 当前图片只看到2个A口，产品背面未展示 | 记录可见证据，不因此把 C口数认定为0 |
| Type-C接口清晰，但没有协议参数 | 可以确认形态；PD、QC和功率保持未知 |

图片计数需要确认产品视图完整，且多张图片不是同一端口的重复视角。USB-A/USB-C 是接口形态，PD/QC 是协议，不能相互推导。快充建议拆成“是否支持、协议集合、明确的功率及适用端口”；只有“快速充电”等宣传词时，可记录原始宣称，不能补出 PD 版本或功率。

现有“USB接口”可以继续作为简洁展示列，后台按子字段保存。只研究接口数量时不用把全部功率细节展示出来。

**六、功率具体规则**

当前“最大功率”“USB功率”“快充”需要建立清晰关系，不能都按全文最大的 W 数值填写。

功率记录应带有：对象（整机/USB/具体端口）、性质（额定/最大/峰值）、数值、单位、适用电压、单口/共享/同时使用条件、原始或推导标记。

| 原始信息 | 正确处理 |
|---|---|
| AC Max 3250 W | 保存整机/AC最大负载功率3250 W，不填到USB功率 |
| USB total output 65 W | 保存USB总功率65 W，不认定每口均为65 W |
| C1 65 W；A1 18 W；USB total 65 W | 分别保存；不把总功率算成83 W，也不判定其必然冲突 |
| C1+A1: 45 W+18 W | 保存同时使用的功率分配场景，不覆盖单口最大能力 |
| 100 V下1250 W，250 V下2500 W | 保存条件值，不只保留2500 W |
| 只有5 V / 3 A | 保存输出参数；默认不填商家明示功率。若启用推导，另存派生15 W与计算条件 |
| 只有额定电压/电流 | 不自动替代产品明示额定功率 |
| 标题65 W，参数20 W且均指同一口同一条件 | 进入冲突；不按来源顺序静默覆盖 |

单口峰值的加和可以大于共享总功率，不能简单要求相加等于总功率。只有明确的同时输出组合才做分配校验。同一产品的不同条件记录不算冲突；相同范围、相同条件下的矛盾才需要裁决。

单位 W/kW 可由程序转换，W/Wh/VA 不混用。默认只转换等价单位，不计算未明示的性能或做营销档位归类。

**七、其他字段的处理边界**

| 字段 | 规则 |
|---|---|
| 线长 | m/cm/mm/ft/inch转换，保留原数值；3 ft＝0.9144 m，不改成1 m。双单位表达在配置的舍入容差内校验；范围或可选长度保留结构 |
| 插孔数 | 明确按每件商品计数，包装数量另存；总孔数与工具专用孔数拆开。墙插端不计入输出插座 |
| 包装数 | 只取当前商品包装数量，不因缺失默认1，不与插孔数相乘后写回每件孔数 |
| 尺寸与体积 | 长宽高使用结构化尺寸；现有叫“体积”却存长宽高的字段应明确语义，兼容原列名。真正体积另设派生字段 |
| 线规/线径 | AWG与毫米直径分开识别，不能直接当普通长度统一换算 |
| 材质/阻燃等级 | ABS、PC+ABS等材质与V0等等级分字段；不能由外观推断材质 |
| 通信与生态 | 无线连接、应用协议、兼容平台、固件分别定义；避免所有名称混放“通信协议” |
| 安全功能/认证 | 保留明确宣称与证据；外形不推出安全能力，宣传标识不自动变成经外部核验的认证 |
| 插孔方向 | 定义相对产品轴线/安装面的参照与角度；视角不足时未知，不随照片旋转改变分类 |
| 特殊功能 | 原始卖点保留；可另映射标准标签。新标签先进入待映射，不自动污染类别字典 |

**八、状态、冲突与人工复核**

避免用“单元格非空＝成功”这一种判断，采用独立维度：

- 执行状态：待处理、处理中、已完成、技术失败。API失败、解析失败、抓取失败有独立原因与次数。
- 值状态：已知、未知、不适用、冲突。已知的数值0、布尔false均为有效结果。
- 复核状态：自动通过、待复核、人工确认。人工确认另带锁定标记、时间与版本。

USB 等对象的每个子字段可以分别已知或未知。正常检查后未找到证据可以完成本轮任务，同时覆盖率仍低于100%；不能为了全满而猜值。

处理规则：

1. 同身份、同范围、同条件候选先标准化再比较；等价表达合并证据，保留原始记录。
2. 不同商品/变体不合并；不同部件或条件分别保存。
3. 同一事实矛盾时进入复核。来源优先级按字段与证据强度配置，不能一律“文本优先”或“图片优先”。
4. 文本证据校验片段确实存在于来源，并检查值是否与证据相容；这仍不等同于商家资料本身必然正确。
5. 复核列表展示商品身份、字段、候选标准值、原文、来源和冲突原因。可接受、修改、保留未知或设为不适用。
6. 人工确认锁定后，重跑只能提出变更建议；原有非空单元格也继续受到保护，但标为“历史值/确认状态未知”。
7. 人工修正单个商品不自动成为全局别名规则；修改字典是独立操作，并先预览受影响结果。

示例：同一子体线长，标题1 m、参数2 m → 状态冲突、标准值不自动定案；确认2 m后锁定。后续新页面写3 m → 新候选与旧确认值并存，提示资料变化。

**九、运行效率、缓存与异常处理**

来源缓存、模型候选、标准化结果、人工确认分开保存。缓存键至少含站点、子ASIN、字段语义版本和来源内容哈希；模型与提示词版本记录在候选中。规则版本变化只重算标准值，不必重抓或重跑模型；字段定义变化则重新检查相关候选是否仍适用。

建议运行选项：仅补缺失、规范已有数据、复核异常、重新提取。默认继续保护已有值；重新提取生成变更建议。

- 网络/限流：有限次数退避重试，保留明确错误。
- 非法JSON/不满足结构：本地验证，允许有限修复；不静默返回空对象当作未知。
- 没有证据：记录来源已检查；输入与规则不变时不无限重试。
- 证据冲突：按需补充相关来源或复核，不对全表多轮投票。
- 停止与恢复：按稳定商品身份和字段恢复，行号用于写回位置映射；重复行保留各行位置，不能串行写错。

模型服务适配：支持严格结构化输出时使用JSON Schema；只支持JSON模式或普通文本时走相应适配，再统一本地验证。不能假设所有OpenAI兼容服务支持同一参数。模型、提示词、规则与来源快照共同用于追踪重复结果；固定这些仍不保证事实正确。

长期结果库建议独立于运行断点；可使用本地SQLite保存版本与证据索引。图片按内容摘要引用，避免在每个字段中重复存图片数据。第一阶段可先沿用日志与结果旁车文件，数据结构保持相同。

**十、Excel 与历史数据迁移**

“规范已有数据”必须是独立入口：扫描唯一值及数量 → 展示原值到标准值的映射 → 分出自动可转换/需复核/保留原值 → 预览受影响行 → 另存结果。原始值和映射规则保留，迁移可追溯。

例如 `1Metre / 1 Metre / 1 m` 统一为数值1；`1m / 3m`保持差异；`3M`如果无法确定是长度而非品牌，不能只按正则替换。旧的“无”需要按字段和原证据判断，不能全局替换为0。

业务表默认只展示常用标准列，例如线长(m)、颜色、USB配置、AC最大功率(W)、USB总功率(W)。类型明确的数字写为数值单元格；复杂端口详情、原文、证据和状态在日志/复核界面查看。新增标准列时建立旧列映射，避免破坏看板、矩阵和趋势统计。

当前写回器会拒绝含数据验证、条件格式、图表、合并等复杂结构的工作簿。初期不直接加入Excel下拉或条件标色；先把约束与复核放在应用界面及日志。若要增加这些Excel能力，必须另行扩展兼容性校验与写回测试。

**十二、分期交付与验收**

| 阶段 | 交付内容 | 验收重点 |
|---|---|---|
| 第一阶段：统一数据口径 | 字段类型/单位/枚举与颜色、USB、功率预设；原始值与标准值；未知/没有分离；站点修正；旧数据规范预览 | 同义值统一，真实差异保留；原始信息可追溯；不误填0；单位可重算；已有人工/历史值保护 |
| 第二阶段：证据与复核 | 逐字段候选和证据、文本图片冲突、端口功率条件、异常列表、人工锁定及变化建议 | 不同来源矛盾能够显示；不靠模型自报分数直接通过；人工值不被重跑覆盖 |
| 第三阶段：持续稳定与效率 | 长期结果库、按内容和规则版本失效、针对性重算、质量报告及下游标准值联动 | 规则改动无需全部重跑；缓存不串站点/子体；稳定性与准确率能分别衡量 |

建立一批固定来源快照与人工标注样本，覆盖各品类、语言、未知、否定、多色、多变体、共享功率和冲突。小规模起步可用50–100个代表商品；这只能作为初始回归集，不能据此宣称总体达到某个准确率。

按字段分别记录：格式合规率、自动接受结果准确率、应提取信息的漏提率、未知被误填率、真实差异误合并率、冲突识别率、重复运行标准值一致率、人工复核比例、每商品调用次数及耗时。持久缓存命中率与模型重复提取一致率必须分开统计。

程序确定性规则与写回保护应在固定边界用例中全部通过；AI效果指标先测基线，再按字段设目标。不能只看整体准确率或承诺100%事实正确。

最低边界用例包括：

- 1Metre、1 Metre、1 m统一；3 ft与1 m不合并；3 m与9.84 ft在已定义的显示舍入容差内核对。
- 黑黄色机身与黑/黄可选子体不同；商品色名保留；主色、配件色不混淆。
- 4USB类型未知不变成4A；只看到Type-C不产生PD；确认无USB不再次补成有。
- 单口65 W、另一口18 W、共享65 W不被相加为83 W；条件功率不会只保留最大数值。
- 缺失、false、0、不适用、抓取失败、JSON失败可以区分；正常未知不无限重试。
- 英国URL不被重构到美站；不同站点同ASIN及不同子体缓存不串用。
- 重复运行不覆盖人工锁定值；字典升级不改写原文；历史迁移不破坏原行、图片、公式与备份保护。
