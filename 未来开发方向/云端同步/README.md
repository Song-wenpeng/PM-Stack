# 未来开发方向：云端同步

自 v1.10.16 起，当前运行版本使用本地 SQLite 作为评论主库，不再加载 Supabase、恢复云端登录会话或创建上传队列。

## 留存内容

- `core_reviews/`：剥离前的云端适配器、业务仓储、同步锁、数据库、采集和界面等源码。
- `migrations/`：原 Supabase 建表、RPC、权限策略与分类迁移 SQL。
- `tests/`：原测试的完整副本，保留同步重试、会话和权限行为依据。它们依赖旧运行环境，不能直接当作现版本测试执行。
- `重构前源码/`：本次重构前的源码快照。
- `retired/`：从当前运行目录移动出的云端模块与 SQL；没有永久删除。
- `requirements-review.lock.txt`：原依赖锁定文件。
- `rescue_cloud_data.py`：一次性读取本机旧登录会话并导出云端评论的迁移工具。只读取原库，导出写入本目录下的 `数据迁移留存/`；不会写入云端或改动原数据库。

## 数据迁移现状

本次尝试恢复原有云端登录会话失败（SupabaseAuthError），无法确认云端是否存在本机没有的评论。原数据未改动。`数据迁移留存/` 已排除 Git 跟踪；其中本地副本已去除云端登录设置。

以后若要补充迁移，需要恢复有效会话或从 Supabase 后台导出。成功运行迁移工具后，应校验评论数、商品关联和标签完整性，再通过现版本本地备份恢复入口加载生成的 `.db`。迁移工具保留本地评论，并将云端评论合并到独立副本中。

## 以后接回云端的前提

1. 保持本地数据主库与本地备份独立可用。
2. 明确账号、工作区切换和数据归属。
3. 定义增量上传、下载、冲突与删除规则。
4. 云端同步不能代替可校验、可恢复的历史备份。
5. 在隔离测试库中验证断网、重试、多机写入和迁移，避免旧队列重新创建已纠正的商品关联。

当前打包配置不包含本目录，也排除了 Supabase 相关运行依赖。
